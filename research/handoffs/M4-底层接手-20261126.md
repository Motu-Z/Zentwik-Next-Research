## 3. 审计结论（按提交范围）

### A2 CO 分层

- `CurveOptimizerBounds`：L2 钳制 −50…+30，拒绝文案明确标注"不对称软限制；AMD 未公开 L1 固件范围"，未冒充固件限制 —— 与 `knowledge/hardware/cpu/amd-curve-optimizer.md` 一致。
- `CurveOptimizerConfig.Resolve` 优先级 Auto > 单核 > CCD > 全核 > 未配置，正确。
- CLI 不做静默钳制（原始值入库，越界在应用阶段以 Skipped + 明示原因返回），未发现"CLI 与底层口径不一致"。
- `Solve` 中 `candidateCores` 含未映射核时按 Skipped 处理，行为可接受。

### A3 FMax（本轮修复）

三处与知识库 `amd-smu.md §4` 不符，已改：

1. 写前不读基线。现写入前读一次基线，`基线 == 0` 判为该平台未实现该消息。
2. 回读要求逐位相等。现按 `IFMaxTuningProvider.ToleranceMhz = 10` 容差判定，`ApplyTarget`/`StateLedger.Commit` 增加等价比较参数。
3. "未配置写命令"与其他失败都表现为 Failed（靠错误文案区分）。现引入 `FMaxWriteResult { Applied, Unsupported, Failed }`，Unsupported 一律落 `Skipped`，不再靠字符串匹配。
4. 输入范围 `[1000, 7000] MHz` 文案改为"软件输入边界，不是固件限制"。

### A4 Intel（本轮重写，未真机验证）

原实现直接写 `0x150` 的低 32 位数据字段：不写邮箱命令字（0x80000011/0x80000010）、不轮询 bit63 忙位、无跨进程互斥。回读同样走裸 MSR 读，硬件未接受时也可能读到刚写入的值，等于"假成功"。

现按 `knowledge/hardware/cpu/intel-oc-mailbox.md §3` 重写：`BuildWriteCommand`/`BuildReadCommand` 把命令字放高端、平面位（核心 0 / GT 1<<8 / Cache 1<<9）、忙位轮询（200 ms）、`Global\Access_Intel_OC_Mailbox` 互斥、写后经读命令回读并按 2 mV 容差校验。位域有单测（`IntelMsrBitsTests`）。

**未验证**：本机为 AMD，`IntelMSR.bin` 在 AMD 上加载返回 ERROR_NOT_SUPPORTED；协议细节来自社区逆向口径（知识库标 Inferred），需 Intel 真机确认命令字、忙位与回读行为。

### B1 服务与 Session 0 通信（本轮修复一半）

运行中的服务（LocalSystem）连接失败的真因不是陈旧二进制，而是**客户端身份校验方式错误**：`PipeIdentity.ReadServerSid` 用 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 打开 SYSTEM 服务进程，普通用户令牌被拒绝（实测错误 5）。改用管道安全描述符所有者（`GetSecurityInfo` + `OWNER_SECURITY_INFORMATION`）后读到 `S-1-5-32-544`（SYSTEM 令牌的默认所有者是 Administrators），据此把可信集合扩展为"当前用户 / SYSTEM / Administrators"。

实测：修复后中完整性 CLI 成功连上 SYSTEM 服务，`status`/`doctor`/`tuning` 均正常返回；Native AOT 版 `zentwik.exe` 同样可连。

**仍未完成**：已安装服务的 `BINARY_PATH_NAME` 仍指向 `.tmp/agent/Zentwik.Agent.exe`（A1 修复前的旧二进制）。从 `tuning` 输出可见旧编码仍在生效：核 3 掩码 `0x00800000`、核 11 掩码 `0x10800000`，正是独热位 `1<<(20+3)` 的形态，SMU 返回 `0xFF`；账本里 `cpu.co.0` 记着 `desired=0 actual=0`，而实际读回核 0 仍为 `-22`，旧二进制的写入-回读不可信。重装需管理员权限，脚本已备好（`.tmp/install-service.ps1`，安装到 `C:\Program Files\Zentwik\Agent`，安装后 `PathName` 不再是临时目录）。

### B2 调度

- `SchedulingWatcher` 生命周期（Start/Stop/Dispose/重启）、配置变更唤醒点（方案保存/删除、场景保存/删除）齐全；`AgentServer` 先停 watcher 再回退场景，顺序正确。
- 优先级方向核对：场景与账本均为"数值大者优先"，`existing.Priority > priority` 拒绝低优先级，一致。
- **本轮修复**：`TryApply` 一次写入亲和性+优先级，任一失败会把两者都记成失败。现拆成两次调用，按字段记账。
- **本轮修复**：CPU Sets 在持续执行路径上不可用时静默跳过；现按方案记一次 WARN，能力恢复后清除告警状态。
- `AffinityScheduler.TryRead`/`TryApply` 增加 `HasExited` 判断，避免对已退出进程读取旧值造成假成功。
- 未处理：PID 复用窗口（账本键 `sched.{pid}.*` 不含创建时间）、>64 逻辑处理器的跨处理器组掩码（当前表现为失败而非静默截断，能力文案已声明限制）。

### C1 休眠唤醒（本轮实现，未真机验证）

新增 `IPowerNotificationSource` 与 `Win32SuspendResumeNotifications`（`PowerRegisterSuspendResumeNotification` + `DEVICE_NOTIFY_CALLBACK`，服务内无需窗口/消息泵），`AgentServer` 订阅后先 `PlanCoordinator.ReconcileAfterResumeAsync()` 再评估场景。

核对规则（针对 `cpu.co.*`、`cpu.fmax`、`cpu.intel.voltage`）：

| 实际值 | 处理 | 计数 |
|---|---|---|
| 等于期望值 | 确认，不写 | Verified |
| 等于前值（退回基线） | 重写期望值，写后回读 | Reapplied |
| 第三值 | 标记用户接管，不覆盖 | TakenOver |
| 读不到 | `LedgerStatus.Unknown`，不写 | Unknown |

`LedgerStatus` 末尾新增 `Unknown`；`StateLedger.IsHeld` 把 `Applied` 与 `Unknown` 都视为"仍持有"，回退、仲裁、单方案应用检查均改用它，避免未知状态变成不可回退。

**未验证**：无真机休眠/唤醒记录；`PowerRegisterSuspendResumeNotification` 在服务会话中的回调时机、重复通知去抖（现 2 秒）需实测。

## 6. 本轮修复（真机验证过程中暴露）

全部已推送 `next`：`6510d3c`、`bb6e41f`、`0c4cf26`、`7dff0be`、`6838064`。

1. **账本前值陈旧**（`6510d3c`）：所有权已释放（Reverted/Failed）时再次应用，原实现沿用旧 `PreviousValue`，`revert` 会把目标写回陈旧快照，覆盖用户此后的手动修改。现按"仍持有则保留基线，已释放则以当前实际值为新基线"处理，`currentValue` 读不到时保守保留旧值。
2. **删除仍持有的方案**（`bb6e41f`）：`plans delete` 原先只检查场景引用，账本条目会变成指向已删方案的孤儿，永久无法回退。现拒绝并提示先回退（退出码 3）。
3. **CPU 调校被误判降级**（`0c4cf26`）：`CpuTuningProbe` 把 `HardwareAvailability.Available` 硬映射为 `CapabilityState.Degraded`；模块聚合又把"另一厂商不在场"算作降级。现 Available → `Running`；`ModuleDefinition` 增加 `AnyOf` 语义，`cpu-tuning`（AMD/Intel 二选一）按任一适用聚合，非适用能力的说明不再拼进模块描述。
4. **PID 复用**（`7dff0be`）：`LedgerEntry` 新增 `ProcessStartTicks`，`Acquire` 写入、清理与回退按创建时间比对。同 PID 的新进程：直接应用路径先丢弃旧条目，持续执行路径判为"已退出"，回退时跳过。旧账本条目该字段为 0，按"进程存活即视为同一目标"保守处理。
5. **状态文件健壮性**（`6838064`）：写入改为 `Flush(flushToDisk: true)` 后再替换；读取失败时先备份 `state.json.corrupt` 再按空状态继续，避免下次保存直接覆盖唯一副本。

测试增至 159 例（Domain 38 / Platform 30 / Core 50 / Contracts 40 / Desktop 2），Release 0 警告。
