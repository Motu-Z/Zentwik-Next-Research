# ADR-007：CLI 作为正式产品入口

- 状态：Accepted
- 日期：2026-11-25
- 相关：ADR-003（进程与权限）、ADR-004（协议）、ADR-005（方案与所有权）

## 背景

WPF 界面开发暂停，需要一条可持续验证业务链路的正式入口。临时测试程序会退化成第二套协议与第二套状态管理；而 GUI 未来可能由其他模型独立开发，因此入口层不能承载领域规则。

## 决策

1. **CLI 是正式产品入口，不是测试脚手架**。它只做参数解析、调用 `AgentConnection`、渲染结果；不引用 `Platform`，不持有设备句柄，不实现领域规则。
2. **业务能力全部下沉到 `Core`**：方案协调、场景引擎、账本、状态存储、诊断由 `Core` 提供，`Agent` 只负责 IPC 会话与生命周期，`Cli` 与未来 GUI 共享同一套服务。
3. **一个命令面对应一类产品能力**：状态（`status`/`caps`/`modules`）、监控（`monitor`/`tuning`）、设置（`settings`）、方案（`plans`）、场景（`scenes`）、所有权（`ledger`）、诊断（`doctor`/`logs`）。
4. **退出码是契约**：`0` 成功、`1` 代理不可用、`2` 用法错误、`3` 操作失败、`4` 能力不可用、`5` 超时、`6` 部分成功。脚本据此分支，不解析文案。
5. **`--json` 输出与人类可读输出共用同一 DTO**，避免两条渲染路径产生信息差。
6. **失败必须可见**：硬件能力不可用时返回具体原因与退出码 4，不回落到"假装成功"。

## 候选

- **只做 GUI，CLI 后置**：无法在当前阶段验证服务化与硬件链路，且 GUI 会先于领域模型成型。
- **CLI 直连 `Platform`**：省一层转发，但会让 CLI 变成特权进程，与 ADR-003 冲突，且未来 GUI 无法复用。
- **脚本驱动的临时测试程序**：不可交付、不可运维、无法作为回归入口。

## 后果

正面：链路可在真实进程与真实管道上端到端验证；GUI 开发只需消费 `Contracts`；脚本与自动化可直接接入。
负面：命令面扩大后需要维护帮助文本与参数校验；JSON 契约变更需同步文档。

## 验证

已在真实进程 + 真实命名管道上验证：`status`、`caps`、`modules`、`tuning`（逐核偏移）、`plans create/apply/revert`（写入-回读-账本）、`ledger`、`scenes create/activate/deactivate`（回退后账本转 `Reverted` 且硬件值归零）、`settings`、`doctor`、`logs`。失败路径验证：能力不可用返回退出码 4 并打印原因。

待验证：脚本消费 `--json` 的稳定性、长时间 `monitor` 的背压表现。
