# Zentwik Next 产品简报

## 产品定位
面向高级用户的系统管理与性能控制平台，覆盖硬件调校、系统策略、进程行为、实时状态和自动化场景。

## 核心领域
- **CPU Tuning**：AMD/Intel 能力发现、电压/频率/功耗/核心分组、基线管理、参数读写验证、方案保存和应用。产品层可统一工作流，硬件提供者负责平台差异。
- **Power Management**：Windows 电源计划、计划参数和 Zentwik 扩展参数。区分计划 GUID、参数、当前生效状态与用户保存状态；应用须考虑部分失败、校验和回滚。
- **Process Scheduling**：进程识别、亲和性、优先级、处理器组和进程生命周期内的策略应用。识别字段必须有明确语义。
- **Monitoring**：CPU/GPU 温度、频率、功耗、利用率、内存、I/O、网络、进程、电源和自动化状态。实时数据与历史持久化分层。
- **Automation / Scenes**：由事件、条件、持续时间、优先级和退出条件驱动，协调多个领域方案，也能执行独立动作。

## 三种独立方案
CPU Tuning Plan、Power Plan、Scheduling Plan 必须保持独立领域对象和生命周期。场景不是第四种方案，而是跨领域协调机制。

## 自动化状态所有权
不能简单地在进入场景时保存快照、退出时无条件写回。需要记录操作对象、前值、目标值、实际值、来源、所有权、优先级、执行结果和恢复资格。用户手动接管后，不得被自动恢复覆盖。

## 模块与能力
模块、能力、业务领域、硬件平台、产品功能和 UI 页面不是同一概念。一个领域可有多个提供者，一个模块可提供多种能力并贡献多个 UI 区块。缺少模块不应使无关功能失效。区分安装、启用、加载、运行和健康状态。

## 插件与国际化
区分内置模块、官方扩展和第三方插件。第三方插件默认独立进程，通过受控 IPC 请求特权操作。插件市场不是第一版前置条件，但应预留版本、权限、隔离和兼容机制。
首批语言 zh-CN、zh-TW、en-US，支持运行时切换、回退和模块资源扩展。用户自建名称保持原样；强调色、主题、信息密度和缩放均可配置。

## 目标与范围
Windows 优先，跨平台按能力逐项定义，不得牺牲 Windows 核心能力。能力分为第一版必须、第一版建议、后续路线图和暂不考虑。新增功能必须说明用户价值、验收标准和维护成本。
