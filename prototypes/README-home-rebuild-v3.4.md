# Zentwik Home Rebuild v3.4 · Masonry Modular Workspace

## 本轮改动：瀑布流首页布局

此前虽然卡片已经可以独立设置高度，但底层使用普通 CSS Grid 的同行轨道。同行最高卡片会撑高整个网格行，导致旁边短卡片下方出现空白。

V3.4 保留 12 列（平板 6 列）的宽度体系，改用独立纵向轨道：
- 每张卡片按自身高度计算占用行数，不再与同行卡片共享高度。
- 新卡片按顺序放入当前最短且宽度足够的连续列组。
- 长卡片只占用自己的列区间；相邻短卡片结束后，其下方空间可立即放置后续卡片。
- 卡片宽度仍按既有 4 / 6 / 8 / 12 列档位调整，二维拉伸、内容管理、自动高度和移除/恢复功能继续保留。
- 内容增减、卡片尺寸变化和窗口宽度变化会触发重新排布。
- 手机窄屏继续使用单列自然流式布局，不套用桌面瀑布流坐标。

## 布局逻辑
排布器按卡片顺序扫描可容纳该卡片宽度的连续列区间，选择当前累计高度最低的区间作为起点。每张卡片根据实际渲染高度映射到细粒度网格行；宽度变化、内容变化或视口变化后重新计算位置。

这不是固定两列瀑布流。12 列仍然支持不同宽度组件，卡片会按可用列宽组合落位。

## 验证
- 桌面端 12 列、平板端 6 列、手机端 390px 布局。
- 构造 620px 高的 GPU 卡片与短内存/自定义卡片，确认短卡片可出现在长卡片旁边及其下方，不必等待长卡片结束。
- 检查组件之间没有几何重叠。
- 桌面与平板/手机视口切换无横向溢出。
- JavaScript 语法检查及页面错误检查通过。

## 限制
- HTML / CSS / JavaScript 独立交互原型，不是 WPF 正式实现。
- 遥测数据仍为演示数据。
- 正式 WPF 实现需要将列占位算法映射到对应布局容器，并在尺寸和内容变化时执行重新排布。
