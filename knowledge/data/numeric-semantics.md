# 数值语义总则

- 规范名称：数值语义总则（Numeric Semantics）
- 领域：`data`
- 核验状态：Verified（通用计算机数值表示）；Zentwik 内部约定为 Proposed
- 权威来源：IEEE 754-2019；ECMA-404（JSON 数字）；MS Learn（Win32 时间/单位 API）
- 相关文档：[units.md](units.md)、[serialization-persistence.md](serialization-persistence.md)、[AI_GUIDE.md](../../AI_GUIDE.md)

## 1. 适用范围

所有在 Zentwik 中出现的数值——寄存器位域、硬件偏移、频率、电压、功率、温度、百分比、IPC 载荷、持久化字段、UI 展示值——在进入代码、磁盘、管道或界面之前，必须先回答三个问题：

1. **有没有单位？** 是纯计数/序号，还是某个物理量？
2. **是原始值还是工程值？** 是硬件寄存器里的整数编码，还是人可读的物理量？
3. **属于哪一层？** 内部计算值、持久化值、IPC 值，还是 UI 展示值？

任何一个问题的答案缺失，都是定义缺陷，不是实现细节。

## 2. 有单位与无单位数值（外部技术事实 / Verified）

| 类别 | 例子 | 特征 | 错误风险 |
|---|---|---|---|
| 无单位计数/序号 | 核心索引、处理器组号、计划版本号、协议版本号 | 只做比较与相等判断，不做加减物理意义 | 被误当作物理量参与换算 |
| 有单位物理量 | 电压、频率、功率、温度、时间窗 | 数值与单位不可分割；换单位必须换算 | 把数字独立传输、丢失单位标签 |
| 步进量（无量纲档位） | AMD Curve Optimizer offset | 是曲线偏移的"档"，每档的 mV 等效值不固定、未公开 | **最常见错误：当 mV 处理** |
| 定点编码值 | Intel 0x150 的 11 位有符号偏移、RAPL energy | 整数表示物理量的缩放编码 | 把编码整数直接当 mV/W 使用 |

**核心区分**：`步进量`和`定点编码值`都长得像整数，但都不是可直接读取的物理量。必须保留"编码→物理量"的换算函数及其单位。

## 3. 原始值与工程值（Raw vs Engineering Value）

- **原始值（Raw）**：从硬件或协议直接读到的整数位模式，可能是补码、缩放定点数或寄存器编码。类型通常是 `u8/u16/u32/u64` 或有符号对应类型。
- **工程值（Engineering）**：应用符号扩展、缩放、偏置之后的人可理解物理量，类型通常是 `f32/f64` 或带单位的强类型。

规则（Zentwik 约定 / Proposed）：

1. 原始值的字段名必须带语义后缀，例如 `rawOffset`、`encodedMicrovolts`，禁止用裸 `value`。
2. 换算只允许在 provider 边界发生一次；`Core` 层只见工程值或明确的强类型。
3. 回读校验必须回到原始值层比较，避免"两次量化"造成的假一致。
4. 换算函数必须是纯函数、有单元测试、覆盖边界（最小/最大/0/负值/溢出）。

## 4. 有符号与无符号整数

- 补码（two's complement）是硬件与 Win32/CLR 的通用有符号表示（Verified）。
- 寄存器字段若声明为 N 位有符号，必须先做**符号扩展**再换算，不能把寄存器整体当 `uint` 后直接除缩放因子。
- 电压偏移、温度差、时间差可以合法为负；功率、能耗、利用率、频率、序号不能为负。取值范围的下界本身就是语义约束。

反例（来自真实历史）：把 Intel `0x150` 的低 32 位整体当无符号数右移 21 位，会把负偏移解析成一个巨大的正数。

## 5. 百分比与比例

- 百分比（0–100）与比例（0.0–1.0）不是同一种值。字段必须显式命名：`usagePercent` 与 `usageRatio`。
- 存储与 IPC 默认使用整数百分比或明确的强类型，避免浮点比较。
- 利用率、负载、核心停泊百分比都是百分比，而 `Processor Performance`（PDH `% Processor Performance`）可以超过 100%（相对标称频率），属于**相对比率**，不得钳制到 100（PDH 计数器语义由 Microsoft 文档 Verified；`research/02` §6 的 155%/std 21pp 等具体观测值原始日志缺失、属报告称/Unknown，见 [measurement-evidence-schema.md](measurement-evidence-schema.md)）。

## 6. 物理量与时间基准（外部技术事实 / Verified）

| 量 | SI 单位 | 常见硬件/界面单位 | 注意事项 |
|---|---|---|---|
| 频率 | Hz | MHz、GHz（×10^6、×10^9） | 倍频 × 100 MHz 是 Intel 常见编码 |
| 周期 | s | ms、µs | 与频率互为倒数；定时器粒度不等于采样精度 |
| 电压 | V | mV（×10^-3）、1/1024 V（定点） | 见 [units.md](units.md) 与 AMD/Intel 两份规范 |
| 电流 | A | mA | 功率 = 电压 × 电流，仅在直流近似成立 |
| 功率 | W | mW、W | RAPL 多用能量累加器差分除以时间窗 |
| 能量 | J | µJ | 累加器会回绕；差分需处理回绕 |
| 温度 | °C | °C、K | 差值的 °C 与 K 数值相同；绝对温度不是 |
| 时间 | s | QPC tick、ms、100 ns | QPC 用于测量间隔；系统时钟用于时间戳 |

时间基准规则：采样间隔用 QPC（单调、高分辨率）测量；显示时间戳用系统时钟；两者不可混用（Microsoft QPC 文档 Verified；`research/02` §6/`research/03` §2.1 的具体采样数字属报告称、原始日志缺失）。

## 7. 寄存器位域、掩码与枚举（外部技术事实 / Verified）

- **位域（bit field）**：寄存器内的连续位，须记录 `[起始:结束]`、宽度、是否带符号、缩放单位。
- **掩码（mask）**：用于位运算的整数常量；区分"单 bit 独热位"与"区间掩码"，二者语义不同。AMD CO 核心地址编码曾在此踩坑（见 [amd-curve-optimizer.md](../hardware/cpu/amd-curve-optimizer.md)）。
- **枚举（enum）**：互斥的命名值；禁止把多个枚举 OR 成"状态码"再当单一状态判断。
- 内存中的字节序：IPC 帧显式小端（依据 ADR-004）；硬件寄存器由平台定义，不得假设与 IPC 一致。

规则：任何位域定义必须同时给出 `shift`、`width`、符号性、单位、合法值集合。缺一项即为 Unverified。

## 8. 四层数值表示（Zentwik 内部约定 / Proposed）

| 层 | 目标 | 表示原则 | 示例 |
|---|---|---|---|
| 内部值 | 领域逻辑计算 | 强类型/工程值，单位明确，可含负值 | `CurveOffsetStep(-10)` |
| 持久化值 | 长期保存与迁移 | 自描述、带 `SchemaVersion`、优先整数或 invariant 字符串 | `{ "coOffset": -10, "unit": "step" }` |
| IPC 值 | 进程间传输 | 与语言无关、小端、可选字段明确、稳定错误码 | JSON 数字 -10，字段名 `coOffset` |
| UI 展示值 | 人读 | 本地化数字格式、单位后缀、合适精度 | `核心 3：偏移 -10 档` |

严禁的行为：

1. 在 UI 层反向解析 IPC 原始整数来"推算"语义。
2. 持久化时丢弃单位信息，依赖代码版本"记得"单位。
3. 用格式化后的字符串（如 `"-10 mV"`）作为跨层传递的载荷。
4. 同一个概念在不同层用不同单位却不显式换算（历史缺陷：早期把 CO 字段命名 `millivolts`、CLI 打印 `offset(mV)`，见 `research/02-hardware-access.md` §11，已纠正）。

## 9. 数值转换规则清单

1. 换算必须用命名函数，不允许裸 `* 1.024`、`/ 1000` 散落各处。
2. 每次换算记录方向（编码 / 解码），并有对称的逆函数。
3. 舍入规则显式化（截断、就近舍入、向零），尤其在有符号负值上。
4. 范围钳制发生在**写入前**，且钳制值来自能力探测而非硬编码猜测。
5. 回读值的比较使用容差（如 FMax ≤10 MHz、Intel 电压 2 mV），容差本身带单位。

## 11. 常见误解与错误用法

| 误解 | 纠正 |
|---|---|
| "整数就没有单位问题" | 定点编码整数携带隐含缩放因子，单位信息在约定里 |
| "-20 表示降低 20 mV" | AMD CO 是档位；等效 mV 不固定且未公开 |
| "回读等于写入就生效了" | 请求型寄存器在锁定时仍可回读写入值；需负载下观测效果 |
| "高频采样等于高信息量" | 短窗口量化噪声不是独立信息；需窗口聚合 |
| "0 就是默认值" | 读到 0 不足以证明默认状态；默认须由 BIOS 恢复默认后、写入前的带日志读取确定。"出厂可能已预置非零偏移"的原归因已因无来源撤回（见 AUDIT §6） |

## 12. 核验状态说明

- Verified：通用数值表示与物理单位；PDH 超 100% 与定时器粒度由 Microsoft 文档支持；采样噪声的具体数字来自仓库报告称（原始日志缺失、来源 Unknown）。
- Inferred：把本项目四层模型作为通用规则推广到其他硬件领域。
- Proposed：Zentwik 的字段命名与分层约定，尚未被产品代码全量落实。
