# 实测数据证据记录规范（Measurement Evidence Schema）

- 规范名称：实测数据证据记录规范
- 英文名称：Measurement Evidence Record Schema
- 领域：`data`
- 核验状态：Proposed（Zentwik 长期写作规则，见 [AUDIT.md](../AUDIT.md) 第三轮）
- 权威来源：第三轮专项审计（实测数据真实性与研究质量）
- 相关文档：[parameter-record-schema.md](parameter-record-schema.md)、[numeric-semantics.md](numeric-semantics.md)、[AI_GUIDE.md](../../AI_GUIDE.md)、[AUDIT.md](../AUDIT.md)

## 1. 目的

本规范防止一类高频错误：**把软件读到的某个数值，直接当成硬件的事实属性（出厂值、默认值、固件行为）**。

典型错误链：某次读取得到非零值 → 写成"出厂即非零" → 被其他文档引用为 Verified 事实 → 后续 AI 据此断言"写 0 不是恢复默认"。每一步都没有原始证据支撑，但结论的语气越来越肯定。读取一个非零值，不足以证明它是出厂值；读取一个零值，也不足以证明设备处于恢复默认状态。

因此规定：**任何声称来自本机/实测/出厂/默认的数据，必须同时记录"数据来源类别"和"读取时的设备状态"，两者缺一即不得写成事实。**

## 2. 数据来源七分类（必须选一，不得混用）

| 类别 | 定义 | 可否当作实测事实 | 标注要求 |
|---|---|---|---|
| User-provided（用户提供） | 用户直接给出的原始数据、自述或截图 | 仅可标为该用户/该次自述的事实，需注明未独立复核 | 注明"用户提供"及提供时间；不得改写成"本仓库实测"或"已验证" |
| Direct observation（直接观测） | 有原始日志、工具原始输出或实验记录支持的观测 | 是（在记录的条件范围内） | 必须附原始日志/输出的位置；无原始记录不得归入此类 |
| Reproduced（可复现） | 按记录步骤可由他人重复得到同样结果 | 是（需步骤完整） | 记录步骤、工具版本、输入、判定标准 |
| Derived（推导） | 由已有数据计算得到 | 否，除非前提数据本身可核验 | 写明推导公式与输入来源 |
| Inferred（推断） | 基于间接证据的推断 | 否 | 写明间接证据与推断链 |
| Example（示例） | 示意或假设数据 | 否 | 显式标"示例"，禁止进入数值表 |
| Unknown（来源不明） | 找不到可靠来源，或来源在追溯中丢失 | 否 | 保留原始表述作历史记录，标 Unknown，给出可执行的补证方法 |

**红线**：Derived / Inferred / Example / Unknown 一律不得改写为实测事实；User-provided 不得升格为 Direct observation（除非另有原始日志）。

## 3. 设备状态分类（必须记录读取时的状态）

读取发生时的设备状态与读取值同样重要。以下状态不得混淆：

1. 出厂状态（未拆封/未刷写，需厂商或购买记录佐证）
2. BIOS 默认状态（BIOS 中 Load Optimized Defaults 后未改任何项）
3. 当前 BIOS 配置（可能已被用户改动过任意项）
4. 当前 SMU / MSR / 寄存器状态（运行时值，可能被多次写入）
5. 用户主动设置后的状态
6. 软件运行时修改后的状态（含工具的后台应用、profile 自动加载）
7. 重启后的状态
8. 恢复默认后的状态
9. 状态未知（无法确定读取前是否发生过修改）

**判定规则**：

- 只有在有证据排除用户修改时，才可标为状态 1 或 2；否则一律标为 **状态未知（9）**。
- 同一会话内如果发生过写入（哪怕只写一个核），该会话内后续读取**不得**称为出厂值或默认值。
- "回读成功"只证明读到的值等于上次写入值，**不证明该值是出厂值，也不证明写入已产生实际效果**（见 §6）。

## 4. 实测记录必填字段（尽可能完整，缺失的写 Unknown）

| 字段 | 说明 |
|---|---|
| 设备型号 | 整机型号 / 主板型号 |
| CPU / GPU 型号 | 具体 SKU，必要时含 stepping |
| BIOS / 固件版本 | 相关固件、驱动、微码版本 |
| 工具及版本 | 读取/写入工具名与精确版本号 |
| 读取或写入接口 | 邮箱命令号 / MSR 地址 / IOCTL / API |
| 测试时间 | 精确到足以定位日志 |
| 测试前状态 | 采用 §3 的状态分类；不确定写"状态未知" |
| 用户是否修改过相关参数 | 是 / 否 / 未知，不得默认"否" |
| 原始数据或日志位置 | 文件路径或仓库内引用；无则写"无原始日志" |
| 测试步骤 | 可复现的操作序列 |
| 结果及其局限性 | 含核验状态与不能推出的结论 |

字段缺失时保持 Unknown 并说明如何补齐；**不允许 AI 自行补齐、推测或以"通常如此"填充**。

## 5. 禁止的归因

- 不得把"读取到非零值"写成"出厂预设了非零值"。
- 不得把"读取到零值"写成"已恢复默认"。
- 不得把"用户自行设置的参数"写成"硬件/固件默认行为"。
- 不得把"工具的输入上限"写成"固件的接受范围"（见 [parameter-record-schema.md](parameter-record-schema.md) L1/L2）。
- 不得把"某个平台的一次实测"推广为"所有平台的结论"。
- 不得把"搜索摘要"标为 Verified；Verified 要求是已打开原始资料并定位到具体章节/字段/代码行。
- 不得把"二手转述、社区经验、其他 AI 生成内容"当作权威依据。
- 不得在原始日志缺失的情况下声称"本仓库实测"。

## 6. 回读（read-back）的语义边界

1. 回读一致 = 写入的值被工具读回，**不等于**该值是硬件默认值。
2. 回读一致 = 寄存器层面的确认，**不等于**效果层生效（请求型寄存器在锁定/保护策略下仍可回读写入值）。
3. 回读一致 = 对本次写入链的确认，**不等于**重启/休眠后仍保持。
4. 要证明"实际生效"，需要负载下的频率、功耗、温度等独立观测量；要证明"出厂值"，需要排除用户修改后的首次读取并有原始日志。

## 7. 四类证据不可互相替代

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 官方资料 | 规范、设计、寄存器定义 | 特定机器的实际行为 |
| 源码 / 上游实现 | 某个版本的具体实现 | 固件/芯片的客观属性 |
| 实机实验 | 特定环境、特定时间的实际行为 | 通用结论（除非可复现且平台覆盖） |
| 用户提供的数据 | 用户提供了什么 | 未经复核的因果归因 |
| 推理 | 在现有证据下可推出什么 | 新的事实 |

## 8. 结论—证据映射表（重要结论必须填写）

| 字段 | 内容 |
|---|---|
| Claim（结论） | 一句话技术结论 |
| Source（来源） | 原始资料或原始数据位置 |
| Location（定位） | 章节 / 页码 / 代码路径与行号 / 寄存器位域 |
| Applicability（适用范围） | 平台、世代、软件版本 |
| Evidence（证据） | 证据如何支持结论 |
| Status（状态） | Verified / Inferred / Unverified |
| Limitation（局限） | 证据不能覆盖的部分 |

一个来源不能自动证明同一文档中的所有结论；每条重要结论单独映射。

## 9. 来源优先级

1. 官方技术文档、规范、手册（须实际打开原文）
2. 官方源码、驱动源码、SDK、上游实现（须定位到具体提交/文件/行）
3. 可信维护者的上游实现
4. 专业技术研究与可复现实验
5. 社区经验与论坛讨论（Inferred，非 Verified）

不得因为多个网站重复同一说法就视为多个独立证据。

## 10. 历史记录与勘误写法

发现无来源数据时：

1. **保留**原始表述作历史记录，不静默删除。
2. 明确标注 Unknown 或"已证伪/已撤回"。
3. 写明是谁、基于什么做出原归因（若可追溯），找不到就写 Unknown。
4. 给出可执行的验证方法或需要用户补充的实验记录。
5. 在 [AUDIT.md](../AUDIT.md) 记录修正过程。

## 11. 案例：CO "出厂 −11…−26" 错误归因（第三轮发现）

- 原表述：`research/02-hardware-access.md` §11 与 `amd-curve-optimizer.md` §8 称"本机 14 个可读核出厂即为非零（−11…−26）"，并在后者标为 Verified 实测。
- 问题：全仓 55 个文件均为 Markdown，**无任何原始日志、ledger、result 文件**；同一段 §11 记载了核 0 被写入 −10，**证明该会话中设备已被修改**，不满足"出厂状态"条件；原始数值、读取时间、工具版本、接口、前置状态均无记录；"出厂"归因的提出者与依据不可追溯。
- 处理：删除"出厂"归因，保留数值作"一次读取的观测记录（原始日志缺失、状态未知）"，标 Unknown；`amd-curve-optimizer.md` 相应条目降级；在 AUDIT 记录。
