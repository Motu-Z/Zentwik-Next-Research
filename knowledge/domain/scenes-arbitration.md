# 场景与仲裁

- 规范名称：场景自动化与冲突仲裁（Scene & Arbitration）
- 英文名称：Automation Scene, Arbitration
- 缩写：无
- 领域：`domain`
- 核验状态：Proposed（项目约定，源自 Accepted ADR-005）
- 权威来源：本仓库 ADR-005、PROJECT_BRIEF、research/01 §5、M2/M3 交接
- 相关文档：[three-plans.md](three-plans.md)、[state-ownership.md](state-ownership.md)

## 1. 定义

场景是**跨领域协调机制**，不是第四种方案。它声明：触发条件（事件/条件/持续时间/退出条件）、引用哪些方案的哪一版、优先级与退出策略。场景也能执行独立动作。

## 2. 仲裁规则（确定性，Proposed）

1. 优先级高者胜。
2. 同优先级按进入时间早者胜（避免抖动）。
3. 再按 ID 序数保证可复现。

多规则命中、按领域冲突消解——不再"一条规则同时决定三块"。

## 2.1 触发条件语义（Verified 实现 2026-11-26）

四类自动触发，语义分两种：持续条件按"此刻是否成立"判断，边沿条件按"上一拍与这一拍的变化"判断。

| 类型 | 参数 | 语义 | 条件不再成立时 |
|---|---|---|---|
| `process` | 进程名 | 持续：进程正在运行 | 停用并回退 |
| `processExited` | 进程名 | 边沿：该进程退出的那一拍成立 | **保持生效，不回退** |
| `powerSource` | `ac` / `dc` | 持续：当前供电侧 | 停用并回退 |
| `manual` | 无 | 只能手动激活 | — |

`processExited` 必须"触发后保持"：退出只发生一拍，下一拍条件必然不成立；若按持续条件处理会当场回退，等于切过去再切回来，动作等于没做。保持状态在三种情况下解除——用户手动停用、场景被删除或禁用、被更高优先级场景接管（闩锁保留，对方让出后仍会复活）。

实现方式：每拍只对配置中出现过的退出触发进程名做查询（`Find` 自带秒级快照，同轮重复查询不重复枚举），与上一拍比对得出"刚退出"。服务启动首拍只记录进程状态、不触发——启动前就退出的进程不该补一次动作。

## 3. 状态所有权与用户接管

- 用户手动接管优先于自动恢复：接管后 `Owner=User` 且 `Restorable=false`，场景退出不得覆盖；只有用户显式释放才恢复。
- 写前记前值 → 写入 → 回读 → 不符即失败。
- 场景版本变更导致跳过；按优先级切换与回退。

## 4. 退出与恢复（Verified 实现）

- 关闭代理时回退活动场景；`RecoverAsync` 只在同一启动周期内补回退遗留写入。
- `RestoreOnExit=false` 的场景保留写入；整机重启后不擅自改写（固件持久化值可能是用户有意保留）。
- 回退失败保留 `Applied` + `Restorable=true` 供重试，不能标"已恢复"。
- 休眠/唤醒重放前必须先读实际值，不能无条件重写（S3 清回出厂假设未验证）。

## 5. 禁止行为

- 无条件快照回写覆盖用户后续修改。
- 一条规则同时决定调校+调度+电源（粒度错位）。
- 回退失败静默标成"已恢复"。

## 6. 常见误解

- "场景是一种方案" → 协调机制。
- "退出场景就恢复一切" → 取决于所有权与 RestoreOnExit。
- "优先级相同随机选" → 按进入时间与 ID 确定性裁决。
